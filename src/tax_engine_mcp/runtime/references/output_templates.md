# 输出格式模板

> 本文件是 `SKILL.md` ⑥ 的下沉版。模板按 ① 判出的类型变，**不要所有题都用同一段结构**：
> 选项判断要逐条列，税负测算要列算式，资格判定要指出卡在哪一条，填空要定位到条款。
> 命令行主线的实际产出由 `tax_answer._print_answer` 排版；本文件的模板是给 Agent 组织
> 最终答案时对照用的骨架。

## 分析六段式

适用 entitlement / liability / treatment / compare。`entitlement` 不套本式【结论】的
"能/不能/部分能"写法，改走下面的「资格判定条件矩阵式」，其余段照旧。

```
## [问题] — [类型中文名]

**结论**：[能/不能/部分能，或算式结论]，一句话

**推理过程**：
1. [条件/事实] → [是否满足]，依据 [第X条]
2. [条件/事实] → [是否满足]，依据 [第X条]
3. [卡点]：卡在 [哪一条]，需要 [什么才能满足]

**立法理由**（必查；取不到要写缺口，不得留白）：[按 ③ 逐层、④ 六源去找官方说明——
  公告的"政策解读"栏、人大审议报告或草案说明、总局新闻办的答记者问。取到才写，照抄
  其意并标出处。六源走空时写"立法理由：未取到官方说明（已查 NPC / 总局 / 360 /
  税屋 / 中国税网 / 公众号）"——整段消失会让读者分不清是查过没查到，还是根本没查。不得凭训练数据补一段
  "为什么这么规定"（⑦ 第 9 条）]

**主依据**：[法规全名]（[文号]，[施行日期]）
  角色：本题的直接规定 / 层级：法律 / 现行有效
  时点：截至 [观察时点] 现行有效

**其余法定依据**：
- [法规名] — [角色] [层级] [时效]

**执行口径与实务认定**：
- [解读文章标题] — [它把上面哪一条落到了什么情形上，与条文分开标出处]

**类案支持**（条件块：`liability`／`entitlement`／`compare` 且题面有争议、追缴、
  资格类比时才发这一轮。没发这一轮=题面不发散；发过而零候选=写了没查到，要按下面
  的零结果形态给一段，两种情形不能混成同一种写法）：
- [来源等级/材料层级] [标题] — [机关]｜[日期]｜案号或文号 [无则写"无"]｜[链接]
  可类比点：[同一事实认定上它怎么说的]
  不可外推点：[它的结论按 [发生时政策] 作出，与本题目标年度不同的那一处]
- 强度上限：官方处理口径，不是司法裁判口径（本通道不含法院判决与复议决定）
- 本轮零候选时改写这一段为检索报告：查了 [几] 轮、用的检索式、覆盖了哪些源、
  排除了几条并为什么、还剩哪些边界没覆盖——结论是"没有官方处理过的同类案件"
  还是"这一层还没查到"，两者说法不同。

**限制条件**：
- 题面未交代 [X]，结论在 [X] 取 [某值] 时成立
- 题面未交代 [Y]，需确认后调整

**制度与流程**（条件块：题面问"这套要求怎么落成制度""谁做、多久一次、留什么痕"，
  或者已经跑过稽查模拟、手上有证据缺口时才发这一段。两样都没有就不发——
  `tax_control` 在这种输入下会拒生成，不会给你一段通用制度。取材是
  `python scripts/tax_control.py --diagnosis gaps.json` 的输出，九要素逐格照抄，
  不自己凑）：
- [活动代号] [环节]／[活动名]｜形态 [针对性制度（基于诊断）／通用模板（基于假设）]
  目的：[这条制度为了让哪一个数字或哪一份材料以后总是答得出]
  责任岗位：[填报的、确认的、复核的、审的各是谁，写到岗位不写到"相关部门"]
  频率：[多久一次，带时点——"每月末""申报期结束后 5 个自然日内"]
  输入资料 / 操作步骤 / 复核点 / 留痕：[各按脚本给出的清单逐条摆，复核点要写成
    判得动的问题，留痕要写成具体那一份件]
  保存期限：[管理下限那一句照抄，后面跟着的"法定年限按 ⑧ 核定的口径为准"不许丢]
  例外处理：[跨项目、跨期、当期取不到这类情形怎么走]
- 本次没牵动到的制度：[脚本「未生成」那一格的条数与清单照摆]
- 本表没有对着它的制度的缺口：[「未被处置的缺口」逐条列名——这一格为空才说明
  制度表覆盖全了，有内容就说明这些缺口目前只有人工处置]

---
> 分析于 [时间戳] | 观察时点 [YYYY-MM-DD] | 数据源: NPC + 总局 + 360 + 税屋 + 公众号
> 免责声明：本内容仅供参考。税收政策以国家税务总局官网、财政部官网、
   主管税务机关的最新公告为准。涉及具体税务处理，请咨询专业税务人员。
```

本式的四条输出红线：

【⑦ 第 12 条正文】**禁止代替用户做申报操作**：只能提供流程指引。
【⑦ 第 13 条正文】**禁止引用已废止法规而不标注**。
【⑦ 第 14 条正文】**禁止省略免责声明**。
【⑦ 第 15 条正文】**禁止省略查询时间戳与观察时点**。

「类案支持」那一块的取材是 `python scripts/tax_cases.py "<主题>" --element <争议要素>`
出来的台账：每条候选的 来源等级、材料层级、机关、日期、案号或文号、链接 六项照台账
原样抄，不自己凑。顺序用 `tax_cases.collect` 排好的那一串（要素命中数 × 子类型权重，
同分按日期倒序），答案里不按读起来顺手的顺序重排——顺序本身是任何人拿同一份候选
都能复算的判据。有候选时每条都要落到"可类比点"与"不可外推点"这两行：只写一句
"官方查处过类似情形"是把台账当装饰，读者看不出它支持本题的哪一步、又在哪一步不能
外推。零候选时给浓缩检索报告（轮次、检索式、覆盖源、排除理由、局限），它的用处是让
读者判断该不该再补一轮，而不是证明"没有先例"。两类写法都不能把这一层说成法定依据：
它不占 L1–L4 位次，主依据栏永远由 ⑧ 定级挑出来的文件占着。

「制度与流程」这一块与「稽查模拟问询式」是一上一下：那一层判"这一问我现在答不答
得出"，本块判"要让这一问以后总是答得出，制度里得写哪一条"，两层的输入输出相接，
问询式吐出的缺口清单就是本块的唯一入口。三条纪律随文本一起进答案：

- **没有诊断就没有处方**（`tax_control.NeedsDiagnosis`）：既没有缺口也没有假设时
  脚本拒生成，回话是"怎么拿到诊断"那两条命令。用户只要通用模板可以生成，但形态
  那一格必须写"通用模板（基于假设）"并把假设逐条摆出来——假设一藏起来，这段文字
  就会被当成企业自己的制度读。
- **只要清单不进这一层**：逐条对着缺口写"本次要补什么"是企业审查那一层的交付物；
  本块给的是责任岗位、频率、输入、步骤、复核、留痕、期限、例外这九格。缺任何一格
  就只是建议不是制度，脚本在载入注册表时按 `tax_control.ELEMENT_KEYS` 逐格判。
- **制度不许碰历史事实**：整改只能把真实发生过的事项的证据补齐、把流程固化，
  伪造、把日期往前写、重做历史资料这类动作在注册表载入时按
  `tax_inspect.FORBIDDEN_REMEDIATION` 扫到即报错。保存期限那一格写的是管理下限，
  法定年限要按 ⑧ 定级挑出的那份文件核对后再定；政策口径不清的缺口，处置仍是回 ⑧
  与 ⑨ 查现行口径，不由制度文本自己定一个口径。

## 逐条比对式

适用 option_judge。

```
## [题干] — 选项判断

**判定**：正确选项为 [A/C/D]（共 [N] 项）

**逐条核对**：

| 选项 | 判定 | 依据条款 | 错在哪 |
|-----|------|---------|-------|
| A. [说法] | 对 | [法名]第X条 | — |
| B. [说法] | 错 | [法名]第X条 | [实际规定为…] |
| C. [说法] | 错 | [法名]第X条 | [实际规定为…] |

**主依据**：[法名]（[施行日期]）[版] — 层级：法律 / 现行有效

**易混点**：[诱饵项几乎总是对应另一部真实规定，去把它取出来——按 ③ 逐层、④ 六源检索
  相邻口径（免税与零税率、差额与全额、分别核算与合并核算这类成对表述），取到才写它错
  在哪一条哪一款。取不到写"易混点：未定位到相邻规定的原文"，空着不写等于把本题最容易
  失分的那一处丢掉]
```

漏一条比答错更严重：**`option_judge` 必须把每个选项都判一遍**，不能只说
"正确的是 A 和 C"。

【⑦ 第 8 条正文】**禁止漏判选项**：选项判断题必须逐条判完。

## 填空式

适用 fill_blank。

```
## [题面] — 术语填空

**填入**：[术语]

**出处**：[法名]第[X]条：[条文原文节选]

**为什么是这个**：[与题干其余部分的对应关系]
```

## 规则陈述式

适用 lookup（含"查询/阅读/分析/解读某份文件"）。点名一份文件时，答案的对象是那
一份文件的规则本身，不是某个纳税人怎么适用它。

```
## [文件全名] — 政策查询

**这份文件讲了什么**：[逐项列出公告实际的规则点，每项一句]

**主依据**：[文件全名]（[文号]，[时效]，[层级]）
  它是本题的直接规定；同一件事的上位授权在下一条并列给出，结论要与它同读
  时点：截至 [观察时点] 现行有效

**其余法定依据**：
- [上位法名] — [法律] [现行有效]；它给了这份文件的哪一条授权或边界

**执行口径与实务认定**：
- [官方解读/实务解读标题] — [与原文不一致或补充了什么，标明出自哪一篇]

**适用边界**：
- 本题答的是规则本身；[主体与身份/地区/金额与规模]未交代，只影响能否套到具体
  纳税人，不影响规则内容。个案适用时要按这几项另行核对
```

四条硬性要求：

- **文号与时效来自录入项**（见 `commands.md` L2），有就照写，没有才写"未标明"；
  不要从标题或文号格式反推时效。
- **【其余法定依据】那一栏若带着"时效判定依据：被现行有效的《……》列为制定依据"**，
  答案要连这一句一起照抄，并保留"引用前按该文自身的时效复核"——这一栏的在效
  结论来自援引证据而不是录入项，只写"现行有效"是把证据链丢掉（见
  `evidence_grading.md` 第 7 条）。
- **只取到官方解读、没取到原文**时，程序给出 `cited_note`，答案必须写明原文待核，
  并把解读放进【执行口径与实务认定】；不得用解读的内容冒充该文件的条文。
- **规则陈述类不问个案**（见 SKILL.md ②）。个案三项写进【适用边界】，不写成追问。

## 资格判定条件矩阵式

是「分析六段式」在 `entitlement` 上的细化。题面给一组事实问"能不能享受某项（或某几
项）优惠"时用这一式，六段式的【推理过程】换成条件矩阵，其余段不动。它解决的是六段式
`[是否满足]` 那一栏只有两个取值带来的漏洞：结论写"部分能"，用户分不清是**自己缺
事实**还是**缺认定/名单/备案**，而这两件事的下一步动作完全不同。

**行判断只有四值**：`满足 / 不满足 / 未知 / 不适用`。没有第五个含糊出口。
**每项优惠的结论只有五档**：

| 结论 | 成立条件 | 必须同时给出 |
|---|---|---|
| 明确匹配 | 全部必要条件都有 ⑧ 够格的依据且判为"满足" | 交互检查（见下）已做完 |
| 条件匹配 | 已知条件全满足，仍有个别必要条件"未知" | 缺的是哪一项、向谁确认 |
| 待资格确认 | 条件取决于认定、名单、备案或主管机关确认 | 认什么、找谁认 |
| 明确不匹配 | 至少一个必要条件"不满足" | 具体排除条款，不能只写"未命中" |
| 无法判断 | 没有够格依据、事实严重不足或超出本技能边界 | 转「依据不足时」出口 |

"条件匹配"与"待资格确认"不得合并成"部分能"：**未知不得升格为满足**，任一必要
条件明确不满足即判"明确不匹配"、不得留在其余绿灯里冒充可享。

```
## [优惠项目] — 条件矩阵

**候选总览**（本题两项以上候选时必填，写在最前）：明确匹配 [n] 项 / 条件匹配 [n] 项 / 待资格确认 [n] 项 / 明确不匹配 [n] 项 / 无法判断 [n] 项

**结论**：[五档之一]

| 政策条件 | 用户事实 | 判断 | 依据（条款原文所在文件） |
|---|---|---|---|
| 主体与身份 | …… | 满足 | 《……》第X条 |
| 交易/项目范围 | …… | 不满足 | 《……》第X条 |
| 业务所属期 | …… | 未知 | 待确认 |
| 金额或比例门槛 | …… | 满足 | 《……》第X条 |
| 认定/名单/核算要求 | …… | 不适用 | 本项无此条件 |

**卡点**：[判为"不满足"的那一条；无"不满足"而有"未知"时写待确认的那一条；全为"满足"或"不适用"则写"无条件卡点，转入交互检查"]

**优惠交互与限制**（结论为"明确匹配"时必填，缺这一段不得下"明确匹配"）：
- 叠加：与本题其他候选项能否同时享受，依据原文里"同时符合 / 不得叠加 / 可叠加 /
  择优 / 同一期间"哪一处措辞。找不到允许叠加的明文时**不得声称可同时享受**，
  降为"条件匹配"并写明缺这一条依据。
- 进项：免税项目对应进项税额的抵扣与转出口径；兼营应税与免税项目时是否要求
  分别核算，无法划分时的处理。
- 开票：开具增值税专用发票对本次匹配范围的影响（按政策规定的交易与票据范围
  判断，不因"已开过票"就判全部收入失去优惠）。
- 放弃优惠：是否允许放弃、放弃范围、起算时点与限制期间。
- 留存：备案、名单、核算与留存资料要求。

**排除项与误用提示**：[相邻易混优惠与它不匹配的具体排除条件]

**同享结论**（本题两项以上候选时必填，写在全部矩阵之后）：[可同时享受的项目组合与允许叠加的明文出处；找不到明文时逐项各写各的档位，不写"都能享"]
```

三条硬性要求：

- **条件矩阵的行来自原文，不来自候选清单**。每行的"政策条件"要能在 ⑧ 够格的
  文件条款里指出来；指不出来就写"未知"，不得按行业标签或企业名称补条件。
- **同一主体名下多笔交易、多项候选优惠都分开成矩阵**，不因主体相同而合并成一个
  结论；免税项与应税项混在一处时，合并判断会把"不能叠加"算成"可同时享"。两项以上
  时先写【候选总览】逐项计数，再逐项给矩阵。
- **不得把"条件矩阵全绿"直接写成"这几项优惠都能享受"**。全绿只说明单项成立，
  【同享结论】要由【优惠交互与限制】那一段的核验结果支撑，两处缺一处即形态不合格。
  【⑦ 第 22 条正文】**禁止未查叠加与择一就给出多项优惠可同时享受**：条件矩阵逐项全绿，只说明每一项
  单独成立；能否同享是另一件事，须回到原文核"同时符合 / 不得叠加 / 可叠加 / 择优 /
  同一期间"的措辞，找不到允许叠加的明文时降为"条件匹配"并写明缺这条依据。免税项目的
  进项转出、兼营是否分别核算、开具专票与放弃优惠的影响同属这一层（模板见
  `references/output_templates.md`「资格判定条件矩阵式」）。

## 计算式

适用 liability 里要出数的那一类。算式由 `scripts/tax_calc.py` 展开，本模板只规定怎么把
它的产出摆进答案。与 ⑦ 第 10 条自洽：摆出来的是算式、参数与出处，供用户和税务机关复核，
不是"你应缴 X 元"的结论。

```
## [税种或项目] — 计算式

**结论限定语**：按下表的参数与这条算式算得 [应纳税额 X 元]；X 是算术结果，
  以主管税务机关核定为准，表内任一参数变动它随之变动。

**逐步算式**（`tax_calc` 输出 `步骤` 里有几条就摆几条，中间量不得省）：
1. [名称] = [算式] → [代入数值后的那一行] = [结果]
2. 累进那一步另摆 `分档`：适用第 [n] 档；逐档 [计入基数 × 税率 = 税额]；
   速算式 [基数 × 税率 − 速算扣除数 = 同一税额]——两条都摆，它们互验的是抄表

**参数与来源对照**：

| 参数 | 值 | 出处 |
|---|---|---|
| [适用税率] | [0.13] | [文件全名（文号），链接] |
| [费用减除] | [60000] | 出处待补 |

**限制条件**：
- 含税/不含税、年度/月度这类口径差落在哪一项参数上，写清
- `无来源参数` 点名的项、未取到的前提各自影响哪一步，写清
```

三条硬性要求：

- **数值一律来自 ③ 检回的现行文件**。引擎里没有税率，所以答案里那个 13% 必须能在
  参数表里指回一份带文号的材料；指不回去就写"出处待补"，不得凭政策记忆填数（⑦ 第 9 条）。
- **`无来源参数` 非空时不得写"参数均来自检回文件"**。那句话一旦被写出而表里还挂着
  "出处待补"，整个答案的可核查性就是假的；逐条列出缺哪一项，说清它影响哪一步。
- **`tax_calc` 报 `缺参数` 就转 ② 补问**，不猜值、不换骨架硬算，也不把手算的数塞进
  这个形态冒充展开结果——那样本模板与逐步比对式就没有区别了。

## 依据不足时

取不到任何现行有效的法定依据时，**明说答不了**，给方向不给具体数额：

```
**依据不足**：本次未取到可作主依据的现行有效条文。

**已查层与结果**（逐层写，一层一格，取到与没取到都要占一格）：
- L1 法律 [给／未给]｜L2 行政法规与部门规章 [给／未给]｜L3 地方口径与公告 [给／未给]
  ｜L4 操作指引与解读 [给／未给]
**未查层与原因**（每个没查的层都要落到一个具体原因）：
- 取值限于 登录墙／验证码／站点不可达／本轮未联网／不适用本题型／已被 ③ 的停止条件
  判为够格——写不出原因的层就是本可以查却没查，那一带"未取到"的话不许说

以下为方向性提示，**不构成结论**：
- 该问题通常依据 [某部法/某类文件]，可在 [哪个库] 检索
- 建议补充 [缺失的前提] 后重新分析

不要用检索到的解读文章代替法定依据来给结论。
```

这两格把"依据不足"从一个形容词变成一条可核对的清单：读者的动作是决定要不要补一轮，
而补哪一层取决于缺口在哪一层，所以「已查层与结果」与「未查层与原因」必须分开写——
合在一起说"没查到"就是把"查过没有"这一个问题取消掉。它与 ⑦ 第 24 条同一条线：
`not_in_library`／`not_checked`／`lookup_failed`／`no_body` 四种状态说的都是本轮没查成
或没连上，读者的动作是补一轮或换词再查；只有 `repealed` 才可以说那份文件不再执行。

## 风险自检专用输出

CHECKPOINT · 风险等级为中或高时，先告知用户"以下分析基于法规
文本，实际风险以主管税务机关判断为准——是否继续？"，等确认后再展开。

```
## [风险关键词] — 合规风险提示

**行为定性**：[该行为在法律上属于什么]

**触发条件**：[什么情况会触发]

**风险等级**：低 / 中 / 高

**后果区间**：[罚则条款 + 裁量幅度，不给单一金额]

**主依据**：[定性的法] 第X条；[罚则] 第Y条

**整改动作**：[从法规中提取的合规要求]

**救济与期限**：[纳税人对处理有异议时的救济路径与法定期限。争议类按 ⑦ 第 2 条要走到
  L4：检索走「税收争议救济」专题，取《税收征管法》里复议前置与可直接起诉的分界，取
  《行政复议法》《行政诉讼法》的申请与起诉期限——分界与期限都以取到的原文为准，条号
  照原文标。取不到写"救济与期限：未取到明文，须向主管税务机关或 12366 确认"，不得删
  段，不得凭记忆给天数]
```

### 账套巡检条件块

这一格只在企业交来了账套行（科目＋金额那一类结构化行，形态见 `data/ledger_rules.json`
的 `_说明`）时展开。没交账套时写"未提供账套行，本块未执行"并说明缺什么，不得整块抹掉。
产出由 `python scripts/tax_ledger.py --ledger ledger.json --params params.json` 生成，
八要素与四类状态由脚本判，Agent 不另判一套；跑之前先 `--pending` 取参数工作清单交给 ③，
回填的每个值都要带来源 URL，没回填的那条规则整条不执行、状态记『待核』。

```
**账套巡检**：覆盖 [complete / partial]｜本次 [n] 条规则｜命中 [k] 条
  层分布 [row n｜calc n｜cross_row n｜global n]｜缺口统计 缺材料 [n]｜政策口径不清 [n]
### [规则代号] [规则名称]（[层]｜[税种]／[场景]｜等级 [低/中/高]）
状态 [已满足/缺/不适用/待核]｜命中 [n] 条｜作用 [n] 行｜未作用 [n] 行
  状态量的是"这条规则判得动吗、判完了没有"，账上有没有问题看命中数与下面的条目
  未作用的行要说清是没落进子集还是整条没执行，不写成"其余各行无风险"
  风险条目八格：行号｜科目｜规则代号｜规则名称｜等级｜明细｜建议｜依据链
    明细＝每一步算式带回的中间量与判据两侧的值；跨行条目的行号与科目是参与聚合的那些行，
    整表性质判时两者渲染成"整表"
    账套自己没给行号那一列时，行号写"第 N 条（该行未给行号）"，N 是按提交顺序数到这一条的序；
    写成"第 None 行"等于没指，只说"未给行号"也指不出是哪几条
    依据链＝每个参数一行：值（＋来源 URL）、检索词、law_hint；没来源就不整条停住
  判不动行：逐行列 [成因] ＋ 这一行缺哪一格 ＋ 动作，成因只有三种（参数未回填／账套缺那
    一格／检回的表里没有那一档），第三种不许借近档顶位
```

与「稽查模拟问询式」的分工：本块比的是账上的数对不对（限额超没超、两处口径差多少、
这一行有没有落进禁止抵扣的范围），那一式判的是检查人员问到这一句时手上有没有能交出去
的材料；判不动的成因直接写成 `tax_inspect` 那两类缺口（缺材料／政策口径不清），可以喂
给 `python scripts/tax_inspect.py --answers`。

【⑦ 第 26 条正文】**禁止把巡检里"判不动"的行合并成"通过"**：账套巡检的三种判不动成因各有各的动作——
参数未回填回 ③ 重取（不许拿旧值顶上），账套缺那一格向企业要那一格的数据（第 25 条），
检回的表里没有那一档换词重取或补一档（不许借邻近档顶位）。三种都不写成"通过"或
"无风险"，逐行判时命中几行出几条条目，未命中的行与判不动的行分开计；比的那两个数
一律来自 ③ 检回并带来源的参数，注册表与代码里出现政策数值就答不出这个数出自哪一号文
（`tax_ledger.validate` 在载入时逐格扫，扫到就报错）。

### 多合同受理条件块

这一格只在企业一次交来几份合同（主合同加补充、变更、解除件），或要判"合同写的与实际做
的是不是同一件事"时展开。一份合同都没给时写"一份合同都没给，本块未执行"并说明缺什么，
不得整块抹掉。产出由 `python scripts/tax_intake.py --intake doc.json`（只看受理与九维度
覆盖）与 `--reconcile doc.json`（再按判断单元逐条比条款与履行）生成，五件套、四个结论值
与三类缺口由脚本判，Agent 不另判一套；跑之前先 `--blank` 出那张表逐格填，抽取来的每一条
都要带原文出处。

```
**多合同受理**：合同 [n] 份｜九维度覆盖 [complete / partial]
  已满足 [n]｜待核 [n]｜缺 [n]｜不适用 [n]（标『不适用』的那一维要带理由）
  待核＝值有了但出处三格缺一格；缺＝这一维没有任何值。没交不等于不涉及，两格各写各的
**合同链**：边 [n] 条（已确认替代 [n]｜待用户确认 [m]）
  逐条列 [边代号] [在先] —[类型]→ [在后]［状态］＋那一句依据的原文
  未确认的边不作废任何条款；动作是先确认，不得择一采用（⑦ 第 23、27 条）

### [判断单元代号]（主体 × 具体应税交易 × 业务所属期 × 资格条件）
**单元四格**：逐格写原文给的那一句；缺哪一格就空着，另起一行把 ② 的追问句问出去
**条款来自**：[这一单元由哪几份合同的条款来说]
**被替代而未采信的条款**：逐条列 [合同／维度代号 维度名／要素（由哪份合同依哪条边替代）]
  没有『采信合同』这一栏——一条已确认的替代边只作废它落到的那几条要素，其余条款
  仍从原合同采信
**核对**：总成对 [n]｜一致 [a]｜矛盾 [b]｜缺一边 [c]｜未取数 [d]｜本次比对维度 [清单]
  一致说的是这一对做成了，不是这一笔业务没问题；范围外的维度要列出"没比不等于没问题"
  差异条目十一格：判断单元｜维度代号｜要素｜槽｜条款侧｜履行侧｜核对结论｜缺口类别｜
    差异说明｜动作｜依据链
    条款侧／履行侧各写值与口径；同一格被两份合同各写一个值时逐个合同列值
    槽写这一对是在 金额／比例／期限／触发时点 哪一格上判的；整条判不动时留空并写成『整条』
    依据链＝两侧各自的出处（文件：位置「摘录」）＋要素落点；填表来的值标『填表，未经抽取核对』
  无法确认条目同这十一格，成因只有五种（条款未提供／履行记录缺失／口径不可比／
    多份合同各写一个值／出处定不到位）；后两种的动作不是要材料——一个先确认合同链关系，
    一个回 ③ 把原文连条款号取回来
**触发时点清单**：逐条 [合同／要素：时点（出处）［来源标记］]——这一张交 ② 的时点轴，
  本块不判那个时点上政策是什么
**证据缺口**：[缺材料／材料矛盾／政策口径不清] ＋ 对象（单元／维度代号 维度名／要素／槽）
  ＋ 按类计数
```

与「账套巡检条件块」的分工：那一块比的是账上两个结构化数（限额、两套口径），本块比的是
同一条要素在合同里写的那一格与实际做过的那一格；两边的判不动成因不同，把本块的『无法
确认』写成巡检的『缺』，读者会以为账上少一栏而向企业要错东西。本块的证据缺口可以直接喂
`python scripts/tax_inspect.py --answers`，差异条目交 `references/tax_risk_framework.md`
与 `scripts/tax_cases.py`，风险等级仍落在上面「风险自检专用输出」的『风险等级』格，
本块不判等级。

【⑦ 第 27 条正文】**禁止把未确认的合同链关系当成生效顺序，禁止把没有出处的抽取当成合同原文**：两份合同
   之间是补充还是替代，只在调用方按边代号确认之后才成立；没确认之前两边的条款都留在比对
   里，不得择一采用（第 23 条），也不得据未确认的替代关系认定旧条款失效。另一头，抽取
   出来的值必须带『文件／位置／摘录』三格出处：缺一格，这一条整条记『待核』且不参与比对
   ——把一个没定位到的数写进『条款侧』，等于让一句没读过的原文替它说话；出处这一格整个
   不给，受理时报错而不是当成没抽取，沉默降级会把猜出来的读成抽出来的。第 25 条管的是
   履行那一侧没记录，本条管的是条款这一侧没原文，两头各判各的。

## 稽查模拟问询式

适用：用户要"站在检查人员的角度看自己"、问"这套账经得起问吗"、或者在整改之前要先
把缺口盘出来。产出由 `python scripts/tax_inspect.py --domain D1 --answers ans.json`
生成，六格与三类缺口由脚本判，Agent 不另判一套。与「风险自检专用输出」的分工：那一种
报"这类事项会触发哪个风险指标"，本种报"检查人员问到这一句时，你手上有没有能交出去的
东西、差哪一份"。

【⑦ 第 11 条正文】**禁止预测稽查结果**：不能说"一定会被查"或"绝对安全"。
能说的只有一句：这一项按 `references/tax_risk_framework.md` 会触发哪个风险指标。

```
## [检查域或事项] — 稽查模拟问询

**覆盖**：[complete / partial]｜本次 [n] 问｜未询问 [m] 问逐条列名——
  没问不等于没问题，这份清单不能当成全项核过
**缺口统计**：缺材料 [n]｜材料矛盾 [n]｜政策口径不清 [n]
**未用的回答**：逐条列代号，成因只有两个——『代号不在注册表里』（照 `--list` 重写代号，
  这份材料目前没参与任何一问的判定）／『本次没问这一格』（放宽筛选范围再跑一次才算问过它）
  这一格非空就说明交来的回答有一部分没被问到，不等于那几问已经核过

### [要点代号] [域]／[主题]
**检查目的**：[检查人员这一问在查什么]
**现有回答**：[企业给的说法原文]；没给就写"未作答"那一格的原话，不替企业编一句回答
**支撑材料**：逐条标 [已有] 或 [缺]，已有的注明它对上企业交的哪一句
**证据缺口**：[缺材料／材料矛盾／政策口径不清] ＋ 对象 ＋ 差额或缺哪一份 ＋ 动作
**可能追问**：[检查人员下一步会问的那一句]
**整改动作**：[把真实发生过的事项的证据补齐、把流程固化下来的那一条]

**一致性核对**：[项A ↔ 项B｜两处数｜差额]，状态取 `一致 / 矛盾 / 缺一边 / 未取数`
**口径**：适用年度 [YYYY]｜依据文件 [全名或文号]
```

三条纪律随答案一起走：

- **不预测稽查结果**（⑦ 第 11 条）：只写这一问缺什么、哪两处数对不上，
  不写被查与被罚的可能。
- **政策口径不清不在本层处置**：动作是回 ⑧ 定级与 ⑨ 类案查现行口径，不由企业自选
  一个口径把这一格填上。
- **整改动作不许碰历史事实**：注册表载入时按 `tax_inspect.FORBIDDEN_REMEDIATION`
  逐条扫这一格，写出补造、倒签、补签、重做历史资料的整改动作直接报错。证据只能补齐
  真实发生过的事项，流程只能往固化的方向改。
